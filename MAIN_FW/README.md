# 메인보드 펌웨어 (ATmega2560 16MHz)

로드셀 컨트롤 보드(SVROCB) 2장을 RS485로 읽어서, 로드셀 10개의 무게(g)와 유무를 RS232로 상위 장치(PC/HMI)에 보냅니다.
상위 장치에서 받은 영점/스팬/LED/감지값 명령은 해당 보드로 전달합니다.

```
상위 장치(PC) ──RS232 38400─── 메인보드(ATmega2560) ──RS485 9600── SVROCB 주소1 (LC 1~5)
                                                               └── SVROCB 주소2 (LC 6~10)
```

## 빌드 / 다운로드
1. Microchip Studio → New Project → GCC C Executable Project → Device **ATmega2560**
2. main.c를 이 `main.c`로 교체하고 `define.h`를 추가한 뒤 빌드(F7)
3. ISP(6핀)로 다운로드. 퓨즈: LOW `0xFF`(외부 크리스탈 16MHz), HIGH `0xD9`, EXTENDED `0xFC`(BOD 4.3V)
   - 아두이노 메가 보드로 시험할 때 ISP로 쓰면 부트로더가 지워집니다.

명령줄 빌드 확인: `avr-gcc -mmcu=atmega2560 -Os -Wall main.c` → Flash 약 6.1KB / RAM 약 1KB

## 핀 (메인보드 회로도가 없어서 임의로 정함 → `define.h`에서 수정)
| 기능 | 핀 |
|---|---|
| RS232 (상위 장치) | USART0 : PE0 RXD0 / PE1 TXD0 |
| RS485 (로드셀 보드) | USART3 : PJ0 RXD3 / PJ1 TXD3 |
| RS485 DE,/RE | PJ2 (HIGH = 송신) |
| STATE LED | PB7 (HIGH = ON) |

아두이노 메가 기준으로는 RS232 = USB 시리얼(Serial), RS485 = 14/15번 핀(Serial3: 14 = TX3, 15 = RX3), DE = PJ2(아두이노 메가에는 핀이 나와 있지 않음), LED = 13번 핀입니다. 회로도가 나오면 `define.h`의 포트 매크로만 바꾸면 됩니다.

STATE LED: 모든 보드 통신 정상이면 0.5초, 끊긴 보드가 있으면 0.1초 간격으로 점멸합니다.

## RS485 : 메인보드 ↔ 로드셀 보드 (Modbus RTU, 메인보드 = 마스터)
- 9600 8N1, 보드 주소 1(DIP 0) = LC1~5, 주소 2(DIP 1) = LC6~10
- 보드를 번갈아 FC03으로 레지스터 0~15(무게, 감지, 에러, ID, FW, raw, 영점 에러)를 읽습니다. 한 번에 약 60ms, 두 보드 한 바퀴 약 120ms입니다.
- 응답 대기 100ms, 연속 3회 무응답이면 그 보드는 통신 끊김(상태 `C`)으로 표시합니다.
- 상위 명령은 FC16으로 씁니다. 영점/스팬은 보드가 EEPROM에 저장할 시간을 0.5초 기다린 뒤 결과 레지스터(26)를 읽어 성공/실패를 판단합니다. 그 동안 다른 보드는 계속 폴링합니다.
- 보드 레지스터 맵은 `SVROCB_FW/README.md`를 보세요.

## RS232 : 메인보드 ↔ 상위 장치 (새로 정한 ASCII 프로토콜)

### 프레임
```
$명령,데이터1,데이터2,...<CR><LF>
```
- **38400** 8N1, ASCII 문자열 (터미널 프로그램으로 바로 보고 보낼 수 있음)
- 메인 → 상위: 체크섬 없이 CR LF(0x0D 0x0A)로 끝납니다. 체크섬을 다시 붙이려면 `define.h`에서 `TX_CHECKSUM 1`로 바꾸면 `...*CS<CR><LF>` 형식이 됩니다.
- 상위 → 메인: `$REQ`처럼 체크섬 없이 보내면 됩니다. 소문자도 받고, 줄 끝은 CR, LF 중 하나만 있어도 됩니다.
  - 체크섬을 붙여 보내도 받습니다(`$REQ*46`). 이때는 `CS` = `$`와 `*` 사이 모든 문자의 XOR 값을 16진수 2자리로 쓰고, 틀리면 `$NAK,CHECKSUM`으로 응답합니다.
- 무게 단위는 g이고 소수점 첫째 자리까지 보냅니다(0.1g). 음수는 `-0.2`처럼 보냅니다.

### 메인 → 상위
| 프레임 | 내용 |
|---|---|
| `$BOOT,101` | 전원 투입 시 1회 (메인 FW 버전) |
| `$DAT,상태,무게1,...,무게10` | 데이터 (자동 송신 또는 `$REQ` 응답) |
| `$ACK,명령,OK` | 명령 처리 성공 |
| `$ACK,명령,NG,사유` | 명령 처리 실패 |
| `$NAK,사유` | 프레임 이상 (`CHECKSUM`, `UNKNOWN`) |
| `$VER,메인,보드1,보드2` | 버전 (통신 끊긴 보드는 0) |
| `$DBG,...` | 통신 진단 결과 |

모든 프레임은 CR LF로 끝납니다.

**`$DAT` 예**
```
$DAT,1000E00000,12.3,0.1,0.0,-0.2,0.0,45.6,0.0,0.0,0.0,0.0
```
- 상태: 로드셀 1~10이 순서대로 한 글자씩 나옵니다.

| 문자 | 의미 |
|---|---|
| `0` | 없음 |
| `1` | 있음 (무게 ≥ 감지 기준) |
| `O` | 있음 + 과부하 (120.0g 이상) |
| `E` | 센서 이상 (로드셀 단선 / 출력 포화) |
| `C` | 보드 통신 끊김 (그 보드의 무게는 0.0) |
| `Z` | 영점 에러: 전원을 켤 때 저장된 영점과 ±5.0g 넘게 다름 (무게 측정 안 함, 0.0). 비우고 전원을 다시 켜거나 `$ZERO,n`으로 해제 |

- 위 예: LC1 있음(12.3g), LC5 센서 이상, 나머지 없음
- 자동 송신(`$AUTO`)이 켜져 있으면 설정 주기마다 보내고, 상태 문자가 바뀌면 바로 보냅니다.

### 상위 → 메인 명령
| 명령 | 예 | 내용 | 응답 |
|---|---|---|---|
| `REQ` | `$REQ` | 데이터 1회 요청 | `$DAT...` |
| `DBG` | `$DBG` | 통신 진단. 보드마다 정상 응답, 무응답, 깨진 응답, 마지막 수신 길이를 보내고 카운터를 0으로 초기화 | `$DBG,120,0,0,37,118,0,0,37` |
| `VER` | `$VER` | 버전 요청 | `$VER,101,101,101` |
| `AUTO,ms` | `$AUTO,500` | 자동 송신 주기 100~10000ms, 0 = 끔(요청 때만). 저장됨, 초기 200ms | `$ACK,AUTO,OK` |
| `ZERO,n` | `$ZERO,3` | 영점. n = 1~10 로드셀 번호, 0 = 전체 | `$ACK,ZERO,OK` |
| `SPAN,n,g` | `$SPAN,3,50.0` | 분동 g(10.0~120.0)을 올린 상태에서 스팬 교정. n = 0이면 전체 | `$ACK,SPAN,OK` |
| `LED,0` | `$LED,0` | 스테이션 LED 자동 (있으면 ON) | `$ACK,LED,OK` |
| `LED,1,비트` | `$LED,1,1010000000` | 스테이션 LED 직접 제어. LC1~10 순서로 `1`=ON | `$ACK,LED,OK` |
| `DTH,on,off` | `$DTH,5.0,3.0` | 감지 기준 g. on 이상이면 있음, off 미만이면 없음 (off ≤ on) | `$ACK,DTH,OK` |

`NG` 사유
| 사유 | 내용 |
|---|---|
| `PARAM` | 값이 범위를 벗어남 / 형식 오류 |
| `BUSY` | 이전 명령을 아직 처리 중 (`ZERO`, `SPAN`, `LED`, `DTH`는 한 번에 하나) |
| `COMM` | 보드 무응답 (1회 재시도 후) |
| `REJECT` | 보드가 값을 거부 (Modbus 예외 응답) |
| `FAIL` | 영점/스팬 실패 (센서 이상, 분동 무게 변화량 부족) |

명령 응답 시간: `ZERO`/`SPAN` 약 0.6초, `LED`/`DTH` 약 0.1초입니다. 전체(n=0) 명령은 보드 순서대로 처리하고, 모두 끝난 뒤 ACK를 한 번 보냅니다.

### 교정 순서 (상위 장치에서)
1. 로드셀을 모두 비운 뒤 `$ZERO,0` → `$ACK,ZERO,OK`
2. 3번 로드셀에 50g 분동을 올리고 1초 기다린 뒤 `$SPAN,3,50.0` → `$ACK,SPAN,OK`
3. 분동을 내리고 다음 로드셀로 넘어가서 반복합니다. 교정값은 각 로드셀 보드의 EEPROM에 저장됩니다.

## 확인이 필요한 항목
1. **핀 / 통신 포트**: 메인보드 회로도에 맞게 `define.h`를 수정하세요(USART 번호를 바꾸면 main.c의 UART 레지스터와 ISR 이름도 같이 바꿔야 합니다).
2. **RS232 속도**: 38400입니다(16MHz에서 오차 0.2%). 115200은 오차가 2.1%라서 글자가 깨졌습니다. 115200이 꼭 필요하면 크리스탈을 14.7456MHz로 바꿔야 합니다(그 경우 `F_CPU`와 타이머 값도 같이 수정).
3. **보드 수**: 보드를 늘리면 `BOARD_NUM`만 바꾸면 됩니다. 로드셀 수와 `$DAT` 필드 수가 같이 늘어납니다.
4. RS485 종단저항(120Ω)은 라인 양 끝(메인보드, 마지막 로드셀 보드)에만 다세요.

## RS485 통신 이상 (`$DAT` 상태가 `C`)
`$DBG`를 몇 초 간격으로 보내서 보드별 카운터를 확인합니다. 형식은 `$DBG,보드1 정상,무응답,깨짐,마지막길이,보드2 정상,무응답,깨짐,마지막길이`입니다. 정상 응답의 길이는 37바이트입니다.

| 증상 | 원인 후보 |
|---|---|
| 무응답만 증가, 마지막 길이 0 | 보드 주소(DIP), 보드 전원, A/B 배선, 메인보드 DE 핀(`define.h` `RS485_*`), 로드셀 보드 퓨즈(16MHz 크리스탈) |
| 깨짐 증가 | A/B 반대, 종단저항, GND 미연결, 통신 속도 불일치 |
| 한 보드만 `C` | 그 보드의 DIP 설정(보드1 = DIP 0, 보드2 = DIP 1), 그 보드 배선 |
| 가끔 `C` | 잡음, 종단저항 위치, 케이블 길이 |

로드셀 보드의 STATE LED는 0.5초 점멸이면 메인보드 요청을 정상 수신 중이고, 1초 점멸이면 받지 못하는 상태입니다. D10(RX)과 D11(TX) LED로 통신 신호가 오가는지 볼 수 있습니다.
